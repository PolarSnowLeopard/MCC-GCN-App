# 批量筛选

**批量筛选** 用于一次性测试多对分子。平台会把任务排进队列、后台跑完后整表呈现。

::: tip 进入页面
点侧边栏 📊 **批量筛选**。
:::

## 用哪个工作流

| 工作流 | 适用 |
| --- | --- |
| [单次预测](./predict) | 单对分子，立刻有结果，便于截图 |
| **批量筛选** | 几对到几千对的 CSV 输入 |

## 操作流程

### 1. 选模型

下拉框与「预测」页一致，所有可见模型可选。日常推荐内置 `MCC-GCN v1`。

### 2. 选输入方式

页面在 **数据输入** 下方有一个分段控件：

- **文本输入** — 一行一对粘贴。
- **上传 CSV** — 上传 `.csv` 文件。

#### 文本输入

在文本框中粘贴分子对，一行一对：

```
api_smiles,coformer_smiles
```

例如：

```
CCO,O=C(O)c1ccccc1O
O=C(O)CCC(=O)O,Nc1ccnc(N)[n+]1[O-]
```

空行和不是两段 SMILES 的行会被静默丢弃。

#### 上传 CSV

点虚线上传区或拖拽文件进去。

CSV 格式：

```csv
api_smiles,coformer_smiles
CCO,O=C(O)c1ccccc1O
O=C(O)CCC(=O)O,Nc1ccnc(N)[n+]1[O-]
```

- 表头行 **可选** — 如果第一行包含单词 `smiles` 会被跳过。
- 两列：`api_smiles`、`coformer_smiles`。

::: tip 没有现成的 CSV？
点击上传区旁的 **下载模板** 按钮，可以下到一个含两行示例的可用模板。
:::

### 3. 提交

点 **开始筛选**。

- 表单会校验已选模型且至少有 1 对有效分子。
- 提交成功会显示 *"批量任务已提交，请到历史记录查看结果"* — 任务进入 Celery 队列。

### 4. 查看进度

进度卡片会出现，显示其中一种状态：

| 状态 | 含义 |
| --- | --- |
| **排队中** | Celery worker 还没开始（轻负载下通常不到 1 秒）。 |
| **运行中** | 模型正在跑。 |

进度条是估计值——实际完成与否以 *"筛选完成"* toast 为准。

::: warning 不要离开页面
离开批量页面会取消页面级的轮询。**任务本身不会停**，可以从 [历史记录](./history) 找回结果，但页内的进度条和结果表不会自动恢复。
:::

### 5. 读结果

任务完成后，下方会出现结果表：

| 列 | 含义 |
| --- | --- |
| **#** | 行号（从 1 开始） |
| **API SMILES** | 输入回显（鼠标悬浮看完整字符串） |
| **Coformer SMILES** | 输入回显 |
| **预测** | 彩色 Tag — `Negative`（灰）/ `Salt`（橙）/ `Cocrystal`（绿）/ `Solvate`（蓝） |
| **置信度** | 4 类概率最大值的百分比 |

每行还会按预测类别浅色着色，便于快速浏览。

### 6. 导出

点结果卡片右上角的 **导出 CSV**，会下载 `batch_results.csv`，列：

```
API SMILES, Coformer SMILES, Prediction, Label, Confidence
```

## 最佳实践

- **先在 [单次预测](./predict) 里试一两行**。比起 5000 行筛完才发现表头错了，1 行的代价小得多。
- **避开 RDKit 不支持的 SMILES**。任何一对中只要有一个解析失败就会变成无预测的行——保持 SMILES 规范。
- **每次提交保持在 ~5000 对以内**。默认管线是 CPU 推理；超大筛选请拆成多次顺序提交，它们都会出现在同一个 [历史记录](./history) 里。
