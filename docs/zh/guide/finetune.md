# 模型微调

如果内置模型对你的化学领域适配不够好，可以用自己的标注数据 **微调** 出一个私有模型。

::: tip 进入页面
点侧边栏 🎯 **微调**。
:::

## 这里的"微调"指什么

你提供一份你已经分类好的分子对 CSV。平台会：

1. 加载你选定的 **基座模型** 权重；
2. 只训练最后几层 dense 层；
3. 保存验证集上表现最好的权重；
4. 在你的账号下登记一个新的模型，状态为 **草稿**。

只要还是草稿，就只对你自己可见。你可以 [测试它](#测试结果)，然后 [发布](#发布结果) 给其他人使用。

## 页面结构

两栏：

- **左** — *微调配置* 表单（用于提交任务）
- **右** — *微调任务* 列表（你过去和正在跑的任务）

## 第 1 步：准备训练数据

表单期望一份带 **三列** 的 CSV：

```csv
api_smiles,coformer_smiles,label
CCO,O=C(O)c1ccccc1O,2
c1ccccc1,CC(=O)O,0
...
```

label 取值：

| 值 | 类别 |
| --- | --- |
| `0` | `Negative` |
| `1` | `Salt` |
| `2` | `Cocrystal` |
| `3` | `Solvate` |

::: tip 没有现成模板？
点上传区旁的 **下载模板** 按钮即可获得起始 CSV。
:::

::: warning 最低要求
训练管线要求 **至少 2 行有效数据**（行内两侧 SMILES 都能解析、label 是合法整数）。少于此数会以 `Need at least 2 valid training samples` 失败。
要让微调真正有意义，目标是 **几十到几百行**，并保持类别分布相对平衡。
:::

## 第 2 步：提交任务

填左侧表单：

| 字段 | 输入 |
| --- | --- |
| **基座模型** | 选一个起点。一般就用内置的 **`MCC-GCN Pretrained v1`**。 |
| **任务名称** | 任意便于辨认的名字，如 `aspirin-derivatives-2026-04`。结果模型文件名会用到。 |
| **训练数据** | 上传你的 CSV（拖拽或点击）。 |

### 高级参数

点 **高级参数** 展开。默认值已经合理 — 没有把握就别动。

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| **Epochs** | `50` | 训练轮数。越大拟合越充分，也越容易过拟合。 |
| **Batch Size** | `16` | 每个梯度步使用的样本数。小数据集用小 batch。 |
| **Learning Rate** | `0.0003` | 优化器步长。默认对大多数情况调过。 |

其他旋钮（`weight_decay`、`train_layers`——解冻多少层 dense 层）使用安全默认。如果你需要调它们，请联系管理员。

点 **提交微调任务**。

## 第 3 步：观察进度

提交的任务会出现在 **右侧** 面板顶部。

点击行展开详情，会看到下列状态之一：

| 状态 | 含义 |
| --- | --- |
| **排队中** | Celery worker 还没开始。 |
| **运行中** | 模型正在训练。第一个 epoch 完成后训练日志开始流式输出。 |
| **已完成** | 训练完成。展示最佳验证 balanced accuracy 和 per-epoch 日志。操作按钮出现。 |
| **失败** | 出错了。错误块里有完整 traceback — 多数是 CSV 不规范或 SMILES 不能解析。 |

::: tip 刷新
任务运行时右侧会自动轮询，但你也可以点面板右上角 **刷新** 强制刷新一次。
:::

## 第 4 步：使用结果

任务完成后，展开行会显示两个操作按钮。

### 测试结果

点 **测试模型**。弹窗里有两个 SMILES 输入框：

1. 输入一对你已知答案的 API + Coformer SMILES。
2. 点 **预测**。
3. 弹窗显示 4 类概率柱状图。用它对微调模型做一次"出厂检查"，再决定是否发布。

### 发布结果

默认情况下结果模型是 **草稿** 状态，只对你可见。

要让平台上其他用户也能用：

1. 点 **发布模型**。
2. 确认。Tag 从 `Draft` 变为 `Published`。

也可以稍后在 [模型管理](./models) 页面发布。

## 读训练日志

每行 per-epoch 日志格式如下：

```
Epoch 12/50 | train_loss=0.2517 train_acc=0.8923 | val_loss=0.3104 val_acc=0.8421 val_bacc=0.8055
```

| 指标 | 含义 |
| --- | --- |
| `train_loss` / `train_acc` | 训练集上的交叉熵 / 准确率 |
| `val_loss` / `val_acc` | 留出 20% 验证集上的同样指标 |
| `val_bacc` | **平衡** 验证准确率 — 平台保存使其最大的 checkpoint |

正常情况下，前若干个 epoch `val_bacc` 持续上升随后趋于平稳。如果 `train_acc` 还在涨而 `val_acc` 已经掉头，那就是过拟合了——减少 epoch 或者扩大数据集。
